在修改 Copilot 知识源文档或检索评测用例前，先运行本地验证脚本。这些脚本不会调用 LLM，也不会验证最终回答质量。它们用于验证文档知识源是否完整，以及轻量本地检索器是否能从 Phase 5A 评测集中命中预期来源页面。

## 验证知识源覆盖

```bash
node scripts/validate-copilot-sources.mjs
```

该检查会验证：

- 每种语言的导航中都有七个 Copilot 数据源页面。
- 导航引用的 Copilot 页面都存在。
- Phase 5A 数据源页面已包含在公开 MDX 知识源集合中。
- 测试、脚本、构建产物、Playwright 报告等排除文件不会被当作商户可见来源。

## 评测检索

```bash
node scripts/evaluate-copilot-retrieval.mjs
```

评测器读取 [检索评测集](/zh/copilot/retrieval-evaluation)，运行本地词法检索，并要求每个用例在 Top-3 结果中返回必须命中的来源页面。

供 CI 或后续 Phase 5B 工具使用时，可以输出 JSON：

```bash
node scripts/evaluate-copilot-retrieval.mjs --json
```

## 构建 Phase 5B 索引

```bash
node scripts/build-copilot-index.mjs --out generated/copilot-knowledge-index.json
```

生成的索引是供下一层 Copilot 服务使用的可移植 JSON 文件。它包含页面 metadata、章节 chunk、token 列表和引用 metadata。除非发布流程明确需要固定版本的产物，否则不要提交生成的索引文件。

## 本地查询索引

```bash
node scripts/query-copilot-index.mjs \
  --index generated/copilot-knowledge-index.json \
  --lang zh \
  --query "Webhook 签名验证失败" \
  --json
```

使用该命令检查下游 Copilot API 将拿到的具体 chunk 和引用。若要评测已构建的索引产物，而不是直接读取 MDX 文件，运行：

```bash
node scripts/evaluate-copilot-retrieval.mjs \
  --index generated/copilot-knowledge-index.json \
  --json
```

## 构建 Phase 5C 回答上下文

```bash
node scripts/build-copilot-answer-context.mjs \
  --index generated/copilot-knowledge-index.json \
  --lang zh \
  --query "API 请求返回 401，应该检查什么？" \
  --json
```

回答上下文包是未来 Copilot 回答 API 的交接对象。它包含：

- 用户问题和语言。
- Top 检索上下文 chunk。
- 页面级 citation。
- 回答模式：`answer_from_docs` 或 `support_handoff`。
- 必须遵守和必须避免的回答规则。
- 可交给 LLM 层使用的 prompt 字符串。

该命令仍然不会调用 LLM。它用于验证在加入模型生成前，检索结果能否被转换成安全、带引用的回答上下文。

## 运行测试

```bash
node --test tests/copilot-local-validation.test.mjs
```

这些检查适合作为知识源质量门禁。本地通过表示文档在结构上已准备好被 Copilot 索引。Phase 5B 索引会在本地验证 chunk 和引用契约，Phase 5C 回答上下文会验证模型输入契约；它们不能替代未来的 embedding、向量检索、答案生成和引用渲染验证。
