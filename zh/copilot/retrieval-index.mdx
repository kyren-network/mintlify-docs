将本页作为 Phase 5A 检索索引契约。它定义哪些文档页面应被索引、如何分类，以及当多个页面匹配同一个商户问题时应优先使用哪些页面。

## 索引规则

- 索引商户文档标签下的公开 MDX 页面，以及下方列出的生成式 API Reference 页面。
- 保留页面语言：`en`、`zh` 或 `zh-Hant`。
- 页面存在 frontmatter 时，保留 `audience`、`product_area`、`intent`、`visibility`、`last_verified_at` 和 `source_owner`。
- 每个 chunk 存储 canonical URL、标题、章节标题、语言和源文件路径。
- 优先检索同语言内容。如果同语言结果较弱，可回退检索英文来源，并用用户语言回答。
- 不索引密钥、本地凭证、私有支持备注或未提交的本地 diff。

## 检索优先级

当多个页面匹配时，按以下顺序排序：

1. 与症状完全匹配的故障排除页面。
2. 精确任务指南或控制台指南。
3. 描述端点结构的 API Reference 页面。
4. 用于简短答案措辞的 FAQ 页面。
5. 用于边界和升级判断的 Copilot 策略页面。

例如，401 问题应优先检索 [API 请求返回 401](/zh/troubleshooting/api-401)，再检索 [认证](/zh/authentication)。请求体 schema 问题应优先检索相关 API Reference，而不是宽泛指南。

## 排除项

不要将这些内容作为商户可见答案来源：

- 草稿计划、内部实施规格、测试 fixture 或本地构建产物。
- 生成的 Playwright 报告。
- 源码注释，除非未来实现明确标记为公开文档。
- 未提交的 `openapi.yaml` 改动，直到它被有意提交并验证。
