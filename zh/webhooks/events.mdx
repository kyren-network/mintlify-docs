启润支付会为以下事件类型发送 Webhook 通知。

## 事件类型

| 事件 | 描述 | 触发条件 |
| --- | --- | --- |
| `order.paid` | 付款已确认 | 客户完成收银台付款 |
| `order.refunded` | 订单退款已生效 | 退款成功 |

当前订单集成不会发送 `order.closed` Webhook。请调用 `GET /v1/orders/{orderId}` 核对 `FAILED`、`CLOSED` 或 `REVOKED` 等未付款终态，参见[订单管理](/zh/dashboard/orders)。

## 事件对象结构

所有 Webhook 事件共享相同的顶层结构：

```json
{
  "id": "evt_abc123",
  "type": "order.paid",
  "created_at": 1736932500000,
  "data": {
    // 事件特定数据
  }
}
```

| 字段 | 类型 | 描述 |
| --- | --- | --- |
| `id` | string | 唯一事件标识符（用于去重） |
| `type` | string | 事件类型 |
| `created_at` | integer | Unix 毫秒时间戳 |
| `data` | object | 事件特定载荷 |

## order.paid

客户成功完成付款时发送。

```json
{
  "id": "evt_abc123",
  "type": "order.paid",
  "created_at": 1736932500000,
  "data": {
    "order_id": "order_def456",
    "product_id": "prod_abc123",
    "customer_email": "customer@example.com",
    "amount": "9.99",
    "currency": "USD",
    "net_amount": "9.29",
    "paid_at": 1736932500000,
    "metadata": { "user_id": "u_123" }
  }
}
```

| 字段 | 类型 | 描述 |
| --- | --- | --- |
| `order_id` | string | 订单 ID |
| `product_id` | string | 购买的产品；无关联产品时可能为空字符串 |
| `customer_email` | string \| null | 客户邮箱地址（如有） |
| `amount` | string | 原始/基础订单金额，不含另向付款人收取的手续费 |
| `currency` | string | 三字母货币代码 |
| `net_amount` | string | 扣除手续费后的金额 |
| `paid_at` | integer \| null | 付款确认时间（Unix 毫秒时间戳，如有） |
| `metadata` | object \| null | Checkout Session 的商户 metadata；内部支付渠道字段会被过滤 |

<Tip>
  这是最重要的事件。用它来完成订单处理 — 例如，为用户的账户充值额度。
</Tip>

## order.refunded

订单退款已生效时发送。你可以用此事件更新权益、余额或对账记录。

有关控制台退款申请流程和退款状态定义，请查看[订单退款](/zh/dashboard/order-refunds)。

```json
{
  "id": "evt_refund123",
  "type": "order.refunded",
  "created_at": 1736932600000,
  "data": {
    "order_id": "order_def456",
    "refund_id": "refund_abc123",
    "refund_status": "PARTIAL",
    "amount": "2.50",
    "currency": "USD",
    "refunded_amount": "2.50",
    "original_amount": "9.99",
    "reason": "customer_request",
    "metadata": { "user_id": "u_123" }
  }
}
```

| 字段 | 类型 | 描述 |
| --- | --- | --- |
| `order_id` | string | 订单 ID |
| `refund_id` | string | 退款 ID |
| `refund_status` | string | 订单退款状态，例如 `PARTIAL` 或 `FULL` |
| `amount` | string | 本次事件对应的退款金额 |
| `currency` | string | 三字母货币代码 |
| `refunded_amount` | string | 本次退款后订单累计已退款金额 |
| `original_amount` | string | 原始/基础订单金额，不含另向付款人收取的手续费 |
| `reason` | string \| null | 退款原因 |
| `metadata` | object \| null | Checkout Session 的商户 metadata；内部支付渠道字段会被过滤 |

## 争议事件（开通后可用）

当你的账户支持并开通争议处理时，还可能收到以下通知。是否可用取决于支付渠道和运营配置，请向 Kyren 支持确认。参见[争议管理](/zh/dashboard/disputes)。

| 事件 | 触发条件 |
| --- | --- |
| `dispute.created` | 争议案件首次匹配到你的订单并成为商户可见案件 |
| `dispute.updated` | 商户可见案件详情或资金投影发生变化 |

两种事件使用相同的顶层结构，`data` 包含以下案件快照；可空字段可能暂不可用：

| 字段 | 类型 | 描述 |
| --- | --- | --- |
| `id` | string | 争议案件 ID，与顶层事件 ID 不同 |
| `provider` | string | 支付渠道 |
| `provider_dispute_id` | string \| null | 渠道争议 ID |
| `order_id` | string \| null | 关联订单 ID |
| `type`, `status` | string | 案件类型和标准化状态 |
| `provider_status` | string \| null | 渠道状态 |
| `amount`, `currency` | string | 案件金额和币种 |
| `reason_code`, `reason` | string \| null | 争议原因 |
| `defendable` | boolean \| null | 是否可提交抗辩（如已知） |
| `response_due_at`, `occurred_at` | integer \| null | Unix 毫秒时间戳 |
| `updated_at` | integer | 案件更新时间（毫秒） |
| `financial_status`, `financial_allocation_status` | string | 案件资金处理状态和分配状态 |
| `settlement_currency` | string \| null | 以下资金金额的币种 |
| `allocated_merchant_principal`, `allocated_rolling_reserve` | string | 本案件分配的商户本金和滚动保证金 |
| `frozen_principal`, `charged_back_principal` | string | 本案件冻结或拒付的本金 |
| `offset_rolling_reserve`, `chargeback_fee` | string | 本案件抵扣的保证金和商户拒付手续费 |
| `projection_state` | string \| null | 关联订单的资金投影状态 |
| `related_case_count` | integer | 共用该订单资金投影的案件数量 |
| `shared_order_projection` | boolean | 是否有多个案件共用资金投影 |

这些通知用于同步案件信息。仅 `status` 变化不代表余额已变动，请结合资金字段和控制台记录对账。即使 `shared_order_projection` 为 true，资金金额仍属于单个案件。

## 处理事件

以下是在 Webhook 端点中处理事件的方式：

```javascript
app.post('/webhooks/kyren', async (req, res) => {
  // ... 先验证签名 ...

  const event = JSON.parse(req.body.toString());

  try {
    switch (event.type) {
      case 'order.paid':
        await handleOrderPaidIdempotently(event.id, event.data);
        break;
      case 'order.refunded':
        await handleOrderRefundedIdempotently(event.id, event.data);
        break;
      case 'dispute.created':
      case 'dispute.updated':
        await handleDisputeIdempotently(event.id, event.data);
        break;
      default:
        console.log(`未处理的事件类型: ${event.type}`);
    }
    res.status(200).send('OK');
  } catch (error) {
    res.status(500).send('Retry later');
  }
});
```

处理函数必须在持久化完成后才确认事件。较长的处理请采用[持久化队列方案](/zh/webhooks/retries)，只有保存成功后才能返回 `2xx`。
