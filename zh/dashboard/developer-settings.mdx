使用开发者设置把你的服务端接入 KyrenPay。

## API 密钥

打开 **控制台 > 开发者工具 > API Keys**（`/dashboard/developers/api-keys`）。如果尚无密钥，点击“生成”并立即保存完整值；已有密钥使用之前安全保存的原始值。完整密钥只在生成时显示，不能复制遮蔽值作为应用配置。将其私下填入服务端的 `KYREN_API_KEY` 或应用对应设置，不要发送到 Agent 聊天中。

API 密钥只能在服务端使用。不要把密钥暴露在前端 JavaScript、移动端应用、日志、截图或公开仓库中。

如果重新生成 API 密钥，需要更新所有调用 KyrenPay 的服务端环境。旧密钥会在重新生成后失效。

## Webhook

配置一个 KyrenPay 可以通过 HTTPS 访问的 Webhook URL。你的服务端应在信任事件内容前验证 Webhook 签名。

打开 **控制台 > 开发者工具 > Webhooks**（`/dashboard/developers/webhooks`），填写应用实际实现的公网 HTTPS 回调地址并保存。首次配置会生成独立的 Webhook Secret；复制完整值，私下填入服务端的 `KYREN_WEBHOOK_SECRET`。如果还没有 Secret，点击“生成”；已有 Secret 使用之前保存的原始值。它不是 API Key，页面上的遮蔽值不能用于验签。重新生成会立即使旧 Secret 失效，需要同步更新相关服务端。不要为了新应用直接覆盖其他应用正在使用的 Webhook URL。

本地 `localhost` 地址不能接收平台通知，需要 HTTPS 部署地址或已授权隧道的当前地址；回调路径以应用实现为准。首笔付款前完成配置，事后配置不会自动补发过去的普通付款通知。

## 产品 ID 与应用配置

在 **控制台 > 产品管理**（`/dashboard/products`）创建或选择价格、币种匹配的 `ACTIVE` 一次性产品，复制列表中的 **产品 ID**。通过 API 创建时读取响应的 `data.id`。将其填入应用的 `KYREN_PRODUCT_ID` 或商品映射；它不是密钥，也不是商户 PID、Checkout ID 或订单 ID。多商品需要各自的映射。

上述变量名是示例，以应用实现为准。填写到实际服务端环境配置后，按应用说明重新加载或重启。所有值必须来自本次接入所选环境的商户后台；development 接入不能混用生产后台与凭证。逐步操作见[快速开始](/zh/quickstart)。

## IP 白名单

如果你的商户账户启用了 IP 白名单，确保所有调用 KyrenPay 的服务器 IP 都已加入。缺少服务器 IP 可能导致认证或授权失败。
