在商户控制台的**争议案件**中查看已匹配到自己订单的案件。案件可用性及资金处理取决于平台和 Provider 是否已为账户及环境启用。列表为空不能证明 Provider 侧没有争议。

## 查看案件

1. 打开**争议案件**，按需使用状态筛选和分页查找案件。
2. 核对 Provider 案件号、订单 ID、案件类型、金额、状态和发生时间。
3. 点击**查看详情**打开详情抽屉。
4. 查看原因、响应截止时间、资金影响和案件时间线。
5. 需要响应时，及时联系 Kyren 支持并提供案件号和订单 ID。

列表及详情抽屉均为只读。提交证据、申诉、修改案件和执行资金操作需要与运营支持协调。**待响应**状态或截止时间不代表系统已自动提交响应。时间线只展示允许商户查看的事件。

## 案件状态与资金

| 项目 | 核对内容 |
| --- | --- |
| 案件状态 | 是否待响应、已提交抗辩材料，或已胜诉、败诉、接受、取消、关闭。 |
| Provider 争议金额 | Provider 报告的案件金额和币种，可能不同于结算币种。 |
| 实际冻结本金 | 已记录为冻结的本金。 |
| 关联滚动准备金 | 与案件关联的准备金。 |
| 已扣本金、已抵扣滚动准备金 | 已记录扣除或用于抵扣拒付的金额。 |
| 拒付费 | 按展示的结算币种记录的拒付费用。 |

活动争议可能冻结受影响资金；符合条件的释放可以返还冻结资金；拒付则扣除受影响本金，并可能抵扣关联准备金及产生拒付费。这些操作取决于资金处理是否启用以及记录的结果。仅凭案件终态不能确认资金操作已经完成，也不能认为已拒付资金已经恢复。

同一订单存在多个关联案件时，详情会提示共享的订单资金上下文。不要将共享金额逐案相加当作独立余额。请结合[资金](/zh/dashboard/funds)、交易流水和[订单](/zh/dashboard/orders)核对实际金额。

## 通知与支持

争议通知启用时，`dispute.created` 和 `dispute.updated` 可以通知你的端点案件变化，详见 [Webhook 事件](/zh/webhooks/events)。通过案件标识关联通知，再查询最新案件及资金记录；案件通知本身不能证明余额操作成功。

案件缺失、即将到期，或资金与案件状态不一致时，请向支持提供商户 ID、Provider 案件号、订单 ID、金额、币种、截止时间和相关时间戳。不要提供 API Key 或 Webhook Secret。
