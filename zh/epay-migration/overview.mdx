如果你已经有 Epay 风格的集成，并希望在迁移到 Kyren Pay 时保留原有请求格式，请使用 Epay 兼容路径。新接入建议优先使用原生 Kyren Checkout，参考[快速开始](/zh/quickstart)，因为原生 Checkout 直接使用 Kyren API 认证和当前订单模型。

通过这些兼容端点创建的 Epay 来源订单，会进入与原生 Checkout 订单相同的 Kyren 订单与结算系统。兼容层只影响入口路径和响应格式。

## 端点映射

| 原 Epay 路径 | 方法 | 用途 | Kyren 行为 |
| --- | --- | --- | --- |
| `/epay/submit.php` | `GET` 或 `POST` | 页面跳转收银台 | 创建或复用订单，然后返回 HTTP `302` 到 `/epay/redirect/{orderId}` 或上游支付页面。 |
| `/epay/mapi.php` | `POST` | 服务端直连创建支付 | 创建或复用订单，并根据渠道返回 `payurl`、`qrcode`、`img`、`trade_no` 等 Epay 风格字段。 |
| `/epay/api.php?act=order` | `GET` 或 `POST` | 订单查询 | 通过 `out_trade_no` 或 `trade_no` 查询。 |
| `/epay/api.php?act=refund` | `GET` 或 `POST` | 退款兼容路径 | 在开通退款权限后，为符合条件的 Epay 来源订单提交退款。 |

## Paydify 加密货币支付

商户一次性加密货币通道绑定 Paydify 后，仍使用 `type=crypto` 与原有 `pid/sign/sign_type=MD5`，不新增 `type=paydify`。未绑定 Paydify 的商户不会因传入 `crypto` 自动切换 Provider。

| 项目 | Paydify 行为 |
| --- | --- |
| `submit.php` | HTTP `302` 跳转到 Kyren 本地支付页 `/epay/redirect/{orderId}`。 |
| `mapi.php` | 返回本地支付页 `payurl`，不返回上游 `qrcode/img`；商户应让买家打开该页面。 |
| 金额 | `money` 是 `money_type` 指定的商品计价金额，省略币种时为 `CNY`；不是应付 USDT 数量。 |
| 买家操作 | 在本地页选择当前可用 App / 网络并确认 USDT 报价后，才创建上游支付和展示该笔二维码。 |
| 商户参数 | 无需提交 App、网络、报价 ID 或 Paydify 专用 `channel_param`；目前仅支持 USDT，不支持 USDC。 |
| 支付确认 | 沿用易支付签名通知和鉴权订单查询；入口返回 `code=1` 或浏览器回跳不代表支付成功。 |

本地页直接展示 Paydify 返回的二维码图片；“打开支付 App”链接需要用户主动点击。当前不将 `httplink` 透传给浏览器，也不把页面 URL 当作上游付款二维码。

以上是接入契约，不表示目标环境已部署或商户已开通；上线前请核实渠道绑定、有效报价和环境验收。本次接入不新增 Paydify 退款能力。详见 [submit.php](/zh/epay-migration/submit-php)、[mapi.php](/zh/epay-migration/mapi-php) 与[迁移检查清单](/zh/epay-migration/migration-checklist)。

## 迁移流程

1. 将 Epay 基础 URL 替换为 Kyren Pay API 基础 URL，并保留兼容路径。
2. 使用 Kyren 发放的 `pid` 和商户密钥进行 Epay 兼容签名。
3. Epay 兼容请求继续使用 `pid + sign` 认证。不要发送 `x-api-key`。
4. 将支付 `type` 映射到支持值，例如 `alipay`、`wxpay`、`creditcard`、`crypto` 或 `paynow`。
5. 浏览器收银台流量接入 [`submit.php`](/zh/epay-migration/submit-php)，服务端创建支付接入 [`mapi.php`](/zh/epay-migration/mapi-php)。
6. 从 `notify_url` 的 GET 通知中校验支付结果，处理完成后返回纯文本 `success`。
7. 使用 [`api.php?act=order`](/zh/epay-migration/api-php) 做兼容订单查询；仅对 Epay 来源订单使用 [`api.php?act=refund`](/zh/epay-migration/api-php) 提交退款。
