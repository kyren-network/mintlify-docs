将现有 Epay 风格集成替换为 Kyren Pay 兼容端点时，请使用此清单。

## 检查清单

- 将旧 Epay 基础 URL 替换为 Kyren Pay API 基础 URL，并保留你使用的兼容路径。
- 设置 Kyren 发放的 `pid` 和商户密钥。
- 发送真实流量前，验证 [Epay MD5 签名](/zh/epay-migration/signature)实现。
- 将支付类型值映射到支持值，例如 `alipay`、`wxpay`、`creditcard`、`crypto` 和 `paynow`。
- 确认 `notify_url` 可访问，并能校验 Epay 兼容通知签名。
- 确认浏览器跳转收银台的 `return_url` 行为。
- 每次处理支付结果通知后返回纯文本 `success`。
- 根据你的集成路径，验证 [`submit.php`](/zh/epay-migration/submit-php) 浏览器收银台或 [`mapi.php`](/zh/epay-migration/mapi-php) 直连创建支付。
- 验证 [`api.php?act=order`](/zh/epay-migration/api-php) 可通过 `out_trade_no` 或 `trade_no` 查询。
- 如需为 Epay 来源订单自动退款，请使用符合条件的已支付订单、已开通退款权限的账户和幂等 `refund_no` 验证 `api.php?act=refund`。
- 对账迁移后的 Epay 来源订单、Kyren 订单与结算。

测试时请使用 Kyren 发放的凭证。低风险真实付款检查仅应在 Kyren 或支持团队批准后进行。
