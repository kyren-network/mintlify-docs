Use this page as the Phase 5A retrieval index contract. It defines which documentation pages should be indexed, how they should be classified, and which pages should be preferred when multiple pages match the same merchant question.

## Indexing rules

- Index public MDX pages in the merchant documentation tab and the generated API reference pages listed below.
- Preserve the page language as `en`, `zh`, or `zh-Hant`.
- Preserve frontmatter fields when present: `audience`, `product_area`, `intent`, `visibility`, `last_verified_at`, and `source_owner`.
- Store each chunk with its canonical URL, title, section heading, language, and source file path.
- Prefer same-language retrieval. If same-language results are weak, retrieve English sources as fallback and answer in the user's language.
- Do not index secrets, local credentials, private support notes, or uncommitted local diffs.

## Retrieval priority

When multiple pages match, rank sources in this order:

1. Exact troubleshooting page for the symptom.
2. Exact task guide or dashboard guide.
3. API reference page for endpoint shape.
4. FAQ page for concise answer wording.
5. Copilot policy page for boundaries and escalation.

For example, a 401 question should retrieve [API request returns 401](/troubleshooting/api-401) before [Authentication](/authentication). A request body schema question should retrieve the relevant API reference before a broad guide.

## Exclusions

Do not use these as merchant-facing answer sources:

- Draft plans, internal implementation specs, test fixtures, or local build output.
- Generated Playwright reports.
- Source code comments unless a future implementation explicitly marks them as public docs.
- Uncommitted `openapi.yaml` changes until they are intentionally committed and validated.
