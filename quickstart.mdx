Follow this guide when you want your server to create Kyren Pay checkout sessions through the API.

If you want to learn the dashboard first, start with [Dashboard overview](/dashboard/overview).

## Prerequisites

- A Kyren Pay merchant account ([sign up here](https://merchant.kyrenpay.com))
- Your API key (found in the Developer section of your dashboard)
- A product created in the dashboard or through the Products API
- A server-side environment where your API key can be stored securely
- A Webhook endpoint for payment notifications before you go live

For one-time payments, the product must be `ACTIVE`, hosted Checkout must be enabled for your merchant, and an enabled channel must support the product's currency and amount. Resolve merchant agreement restrictions when applicable. Product creation alone does not guarantee an available payment method. Current per-order caps are USD 630.00, CNY 4,000.00, HKD 5,000.00 and IDR 10,000,000.00; channel and merchant limits may be lower. If an API IP whitelist is configured, allow your server's outbound IP.

Before the first payment, configure a public HTTPS Webhook URL and obtain its separate Webhook Secret in **Developer Tools > Webhook Settings**. This is not your API Key. Unconfigured Webhooks do not queue ordinary `order.paid` events; later configuration does not automatically replay past payments.

## Step 1: Get your API Key

After signing up, navigate to **Dashboard > Developer Tools > API Keys**. A full key is shown only when generated. Use your securely stored original value, not its masked display. Regeneration immediately invalidates the old key.

- **Live key**: `kyren_live_xxxxxxxxxxxx` — use this for production

<Warning>
  Keep your API keys secure. Never expose them in client-side code or public repositories.
</Warning>

Privately put the full value in your application's server-side `KYREN_API_KEY` setting, not in an Agent chat. Generate a key on this page if none exists. If you already have one, use its securely saved full value rather than regenerating it as a routine integration step.

### Configure Webhook and get its Secret

1. Open **Dashboard > Developer Tools > Webhooks**.
2. Enter your application's actual public HTTPS callback URL in **Webhook URL** and save, for example `https://your-app.example/webhooks/kyren`. Use the path implemented by your application. Kyren cannot reach localhost; local testing needs a reachable HTTPS host or an authorized tunnel.
3. First configuration generates a Webhook Secret. Immediately copy its full value into your application's private server-side `KYREN_WEBHOOK_SECRET` setting. If no Secret exists, click Generate.
4. If a Secret is already configured, use its securely saved original. Its masked display cannot verify signatures. Regeneration immediately invalidates the old Secret and requires updating every server that uses it; do not rotate it as a default setup step.

The Webhook Secret and API key are different values. An existing Webhook URL may serve another application; confirm its use before changing it. See [Developer settings](/dashboard/developer-settings).

This guide uses production addresses. If your integration selects a Kyren-provided development or other environment, use that environment's dashboard, API Base URL and matching credentials throughout instead of switching to the production examples.

## Step 2: Create a Product

In **Dashboard > Product Management**, create or select an `ACTIVE` one-time product with the agreed price and currency. Copy its **Product ID** from the product list into your application's server-side `KYREN_PRODUCT_ID` setting.

Alternatively, use the Products API to create a product that represents what you're selling:

```bash
curl -X POST https://api.kyrenpay.com/v1/products \
  -H "Content-Type: application/json" \
  -H "x-api-key: kyren_live_xxxxxxxxxxxx" \
  -d '{
    "name": "1000 AI Credits",
    "description": "Top up 1000 credits for AI API usage",
    "price": "9.99",
    "currency": "USD"
  }'
```

Save `data.id` from the JSON response. For example, `{ "code": 0, "message": "success", "data": { "id": "prod_abc123" } }` illustrates the envelope with other product fields omitted.

A product ID is not a secret, merchant PID, Checkout ID or order ID. `KYREN_PRODUCT_ID` is the setting name in a single-product example; for multiple products, store a server-side mapping from each local SKU to its Kyren product ID. Use your application's actual setting names and reload its server configuration according to its startup instructions.

## Step 3: Create a Checkout Session

When a customer wants to pay, create a checkout session:

```bash
curl -X POST https://api.kyrenpay.com/v1/checkouts \
  -H "Content-Type: application/json" \
  -H "x-api-key: kyren_live_xxxxxxxxxxxx" \
  -d '{
    "productId": "prod_abc123",
    "successUrl": "https://yoursite.com/success",
    "cancelUrl": "https://yoursite.com/cancel",
    "displayMerchantName": "Campaign Store",
    "metadata": { "businessOrderId": "purchase_123", "userId": "user_123" }
  }'
```

Use `displayMerchantName` when this checkout should show a campaign, store, or app name that differs from your account name.

The response is `{ "code": 0, "message": "success", "data": { ... } }`. Read `data.id`, `data.url`, `data.amount`, `data.currency` and `data.expiresAt` (Unix milliseconds), and persist them against your server-generated business order before returning its URL to the browser. Product ID, user identity and metadata must come from trusted server records. Session amount and currency come from the product; price, quantity and currency overrides are not supported.

Create one pending Session per business purchase and reuse it on repeated clicks. Sessions expire after 24 hours. The API has no Checkout creation idempotency key, so persist a creation reservation and reconcile timeouts or failed local saves before creating another Session. See the [full example](/guides/collect-first-payment).

## Step 4: Redirect to Checkout

Redirect the customer to the checkout URL returned in Step 3. They will see a hosted payment page where they can choose their preferred payment method.

```javascript
// Example: redirect in your web app
// checkoutUrl is supplied by your authenticated backend, from Kyren's data.url.
window.location.href = checkoutUrl;
```

## Step 5: Handle the Webhook

After payment, Kyren Pay sends a signed JSON POST to your configured Webhook URL. Register the raw-body route before any global JSON parser. The following route requires the [signature function](/webhooks/signatures) and the durable inbox adapter described in the [full example](/guides/collect-first-payment):

```javascript
const crypto = require('crypto');

function verifyWebhookSignature(payload, signature, timestamp, secret) {
  if (typeof secret !== 'string' || !secret) return false;
  if (typeof signature !== 'string' || !/^sha256=[0-9a-f]{64}$/.test(signature)) return false;
  if (typeof timestamp !== 'string' || !/^\d+$/.test(timestamp)) return false;
  const sentAt = Number(timestamp);
  if (!Number.isSafeInteger(sentAt) || Math.abs(Date.now() - sentAt) > 300000) return false;
  const data = `${timestamp}.${payload}`;
  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(data)
    .digest('hex');

  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(signature)
  );
}

app.post('/webhooks/kyren',
  express.raw({ type: 'application/json' }),
  async (req, res) => {
    const signature = req.headers['x-kyren-signature'];
    const timestamp = req.headers['x-kyren-timestamp'];
    if (!Buffer.isBuffer(req.body)) return res.status(400).send('Raw JSON body required');
    const payload = req.body.toString('utf8');

    if (!verifyWebhookSignature(payload, signature, timestamp, process.env.KYREN_WEBHOOK_SECRET)) {
      return res.status(400).send('Invalid signature');
    }

    let event;
    try { event = JSON.parse(payload); } catch { return res.status(400).send('Invalid JSON'); }
    if (!event || typeof event.id !== 'string' || !event.id || typeof event.type !== 'string' || !event.data) {
      return res.status(400).send('Invalid event');
    }
    try {
      await webhookInbox.insertIfAbsent(event.id, event);
    } catch {
      return res.status(503).send('Retry later');
    }
    res.status(200).send('OK');
  }
);
```

<Info>
  Configure your URL in **Dashboard > Developer Tools > Webhook Settings**. Verify, persist, then return `2xx` within 10 seconds. A durable worker must retry failures, deduplicate event IDs and credit each business order only once using a unique Kyren order ID and a database transaction.
</Info>

`successUrl` and `cancelUrl` are browser navigation, not payment evidence. Your backend can query `GET /v1/checkouts/{id}`: `OPEN` is pending, `COMPLETE` includes the successfully associated `orderId`, and `EXPIRED` closes the Session. For missed notifications, query `GET /v1/orders/{orderId}`, verify payment and its product/base amount/currency/metadata association, and use the same idempotent fulfillment transaction as Webhooks. Session creation does not return an `orderId`. Use the exact returned `data.url`. `successUrl` is required; `cancelUrl` is optional.
