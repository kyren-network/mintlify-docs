在修改 Copilot 知識源文檔或檢索評測用例前，先執行本地驗證腳本。這些腳本不會呼叫 LLM，也不會驗證最終回答品質。它們用於驗證文檔知識源是否完整，以及輕量本地檢索器是否能從 Phase 5A 評測集中命中預期來源頁面。

## 驗證知識源覆蓋

```bash
node scripts/validate-copilot-sources.mjs
```

該檢查會驗證：

- 每種語言的導航中都有七個 Copilot 資料源頁面。
- 導航引用的 Copilot 頁面都存在。
- Phase 5A 資料源頁面已包含在公開 MDX 知識源集合中。
- 測試、腳本、建置產物、Playwright 報告等排除檔案不會被當作商戶可見來源。

## 評測檢索

```bash
node scripts/evaluate-copilot-retrieval.mjs
```

評測器讀取 [檢索評測集](/zh-Hant/copilot/retrieval-evaluation)，執行本地詞法檢索，並要求每個用例在 Top-3 結果中返回必須命中的來源頁面。

供 CI 或後續 Phase 5B 工具使用時，可以輸出 JSON：

```bash
node scripts/evaluate-copilot-retrieval.mjs --json
```

## 構建 Phase 5B 索引

```bash
node scripts/build-copilot-index.mjs --out generated/copilot-knowledge-index.json
```

生成的索引是供下一層 Copilot 服務使用的可攜式 JSON 檔案。它包含頁面 metadata、章節 chunk、token 列表和引用 metadata。除非發布流程明確需要固定版本的產物，否則不要提交生成的索引檔案。

## 本地查詢索引

```bash
node scripts/query-copilot-index.mjs \
  --index generated/copilot-knowledge-index.json \
  --lang zh-Hant \
  --query "Webhook 簽名驗證失敗" \
  --json
```

使用該命令檢查下游 Copilot API 將拿到的具體 chunk 和引用。若要評測已構建的索引產物，而不是直接讀取 MDX 檔案，執行：

```bash
node scripts/evaluate-copilot-retrieval.mjs \
  --index generated/copilot-knowledge-index.json \
  --json
```

## 構建 Phase 5C 回答上下文

```bash
node scripts/build-copilot-answer-context.mjs \
  --index generated/copilot-knowledge-index.json \
  --lang zh-Hant \
  --query "API 請求返回 401，應該檢查什麼？" \
  --json
```

回答上下文包是未來 Copilot 回答 API 的交接物件。它包含：

- 使用者問題和語言。
- Top 檢索上下文 chunk。
- 頁面級 citation。
- 回答模式：`answer_from_docs` 或 `support_handoff`。
- 必須遵守和必須避免的回答規則。
- 可交給 LLM 層使用的 prompt 字串。

該命令仍然不會呼叫 LLM。它用於驗證在加入模型生成前，檢索結果能否被轉換成安全、帶引用的回答上下文。

## 執行測試

```bash
node --test tests/copilot-local-validation.test.mjs
```

這些檢查適合作為知識源品質門檻。本地通過表示文檔在結構上已準備好被 Copilot 索引。Phase 5B 索引會在本地驗證 chunk 和引用契約，Phase 5C 回答上下文會驗證模型輸入契約；它們不能替代未來的 embedding、向量檢索、答案生成和引用渲染驗證。
