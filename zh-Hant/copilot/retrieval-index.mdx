將本頁作為 Phase 5A 檢索索引契約。它定義哪些文檔頁面應被索引、如何分類，以及當多個頁面匹配同一個商戶問題時應優先使用哪些頁面。

## 索引規則

- 索引商戶文檔標籤下的公開 MDX 頁面，以及下方列出的生成式 API Reference 頁面。
- 保留頁面語言：`en`、`zh` 或 `zh-Hant`。
- 頁面存在 frontmatter 時，保留 `audience`、`product_area`、`intent`、`visibility`、`last_verified_at` 和 `source_owner`。
- 每個 chunk 儲存 canonical URL、標題、章節標題、語言和源檔案路徑。
- 優先檢索同語言內容。如果同語言結果較弱，可回退檢索英文來源，並用使用者語言回答。
- 不索引密鑰、本地憑證、私有支援備註或未提交的本地 diff。

## 檢索優先級

當多個頁面匹配時，按以下順序排序：

1. 與症狀完全匹配的故障排除頁面。
2. 精確任務指南或控制台指南。
3. 描述端點結構的 API Reference 頁面。
4. 用於簡短答案措辭的 FAQ 頁面。
5. 用於邊界和升級判斷的 Copilot 策略頁面。

例如，401 問題應優先檢索 [API 請求返回 401](/zh-Hant/troubleshooting/api-401)，再檢索 [認證](/zh-Hant/authentication)。請求體 schema 問題應優先檢索相關 API Reference，而不是寬泛指南。

## 排除項

不要將這些內容作為商戶可見答案來源：

- 草稿計劃、內部實施規格、測試 fixture 或本地構建產物。
- 生成的 Playwright 報告。
- 源碼註釋，除非未來實現明確標記為公開文檔。
- 未提交的 `openapi.yaml` 改動，直到它被有意提交並驗證。
